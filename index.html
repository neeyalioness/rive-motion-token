    01แยกสองชั้น: Inner กับ Outer
    

    
  
    Inner · อยู่ในไฟล์ .rivหมุน, morph วงกลม → หัวใจ → ดาว, สีของแต่ละ state Designer ทำใน Rive Editor ฝั่ง code คุมได้ผ่าน View model (data binding) เท่านั้น
    
  
    Outer · อยู่ใน codeการเคลื่อนไหวของกล่องที่ห่อ Rive: enter, exit, change, emphasis ทำด้วย CSS / Compose / SwiftUI และใช้ token ได้ตรง ๆ
    

    

    State machine inputs ถูก deprecate แล้วเอกสารของ Rive แนะนำให้ใช้ Data Binding (View model) แทน inputs ทั้ง state และ props จึงอยู่ใน View model ตัวเดียว
    

    


    

    02แต่ละชั้นของ token ต้องมีค่าอะไร
    

    เปรียบให้เห็นภาพ: ref คือกล่องสีที่มีทุกเฉด, sys คือกฎว่า “ปุ่มหลักใช้สีไหน”, comp คือการระบุว่า “ขอบของ spinner ทำตามกฎปุ่มหลัก” ถ้าเปลี่ยนกฎ (scheme) ทุก component ที่อ้างกฎนั้นเปลี่ยนตามทันที
    

    

    Fieldref · primitivesys · semanticcomp · component
    


    ชื่อตามค่า
    cml.ref.motion.duration.250    		ตามหน้าที่
    cml.sys.motion.transition.enter.scale    		ตามชิ้นส่วน
    cml.comp.spinner.container.enter
    

    ชนิด ($type)duration, cubicBezier, spring, number, colorเหมือน ref หรือ composite (transition)เหมือน sys ที่อ้าง
    

    ค่าค่าจริง + หน่วย (250ms)alias ไปหา ref แยกตาม mode (professional / natural / playful / reduced)alias ไปหา sys ตัวเดียว ไม่แยก mode
    

    คำอธิบายสั้น ๆ ว่าคืออะไรหน้าที่, ใช้เมื่อไร, ห้ามใช้เมื่อไรใช้ที่ส่วนไหนของ component
    

    ที่มา / เหตุผลไม่จำเป็นจำเป็น: ลิงก์ M3 หรือผลทดสอบของทีมเฉพาะเมื่อ component ใช้ค่าต่างจากปกติ
    

    Override ได้ไหม–ผ่าน scheme เท่านั้นระบุว่าคนเรียกใช้ส่งค่าอื่นได้หรือไม่
    

    เจ้าของDSDSDS + เจ้าของ component
    

    

    กฎสำคัญcomp ต้องอ้าง sys เสมอ ห้ามอ้าง ref ตรง ๆ เพราะ ref ไม่มี mode ถ้าข้าม sys การสลับ scheme จะไม่มีผลกับ component นั้น
    

    


    

    03Token resolution ทีละเคส
    

    ทุกเคสใช้ spinner ตัวเดียวกัน ดูว่าชื่อ token ไหนคงเดิมและค่าไหนเปลี่ยน
    


    
  
    เคส 1 · ค่าเริ่มต้น
    
  
    หน้าเว็บตั้ง scheme = professional · spinner ไม่ได้ส่ง prop อะไรเพิ่ม · เล่น enter
    
  
    compcml.comp.spinner.container.enter→sys · mode professionalcml.sys.motion.transition.enter.scale→refduration.250 + easing.standard-decelerate→value250ms · cubic-bezier(0,0,0,1)
    
  
    ทำไม: ของที่เข้ามาใหม่ใช้ decelerate (เร็วตอนเริ่ม ชะลอตอนถึง) ให้ตาจับตำแหน่งสุดท้ายได้ professional ใช้ชุด standard ที่ไม่มี overshoot
    

    


    
  
    เคส 2 · Override scheme ที่ตัว component
    
  
    หน้าเว็บเป็น professional แต่ spinner ตัวนี้ส่ง motionScheme="playful"
    
  
    compcml.comp.spinner.container.enter→sys · mode playfulcml.sys.motion.transition.enter.scale→refspring.expressive-spatial-fast→valuestiffness 800 · damping 0.6
    
  
    ทำไม: ชื่อ comp และ sys ไม่เปลี่ยนเลย สิ่งที่เปลี่ยนคือ mode ที่ sys ใช้เลือก ref นี่คือเหตุผลที่ไม่ใส่ชื่อธีมในชื่อ token
    

    


    
  
    เคส 3 · ผู้ใช้ตั้งลดการเคลื่อนไหวใน OS
    
  
    prefers-reduced-motion: reduce · wrapper เปลี่ยน mode เป็น reduced เอง
    
  
    compcml.comp.spinner.container.enter→sys · mode reducedcml.sys.motion.transition.enter.scale→refduration.150 + easing.linear + scale.100→value150ms · fade อย่างเดียว
    
  
    ทำไม: ยังมี feedback ว่าของปรากฏขึ้น แต่ไม่มีการขยับตำแหน่งหรือขนาด ซึ่งเป็นสิ่งที่ทำให้ผู้ใช้บางกลุ่มเวียนหัว คนเรียกใช้ไม่ต้องเขียนอะไรเพิ่ม
    

    


    
  
    เคส 4 · Status error + emphasis
    
  
    งานล้มเหลว · wrapper ตั้ง status = error แล้วเล่น emphasis ให้อัตโนมัติ
    
  
    compcml.comp.spinner.rive.status.error.color→syscml.sys.color.status.error→refcml.ref.palette.red.50→value#D93A3A
    
  
    compcml.comp.spinner.container.emphasis.error→syscml.sys.motion.transition.emphasis.shake→refduration.300 + offset.4→value300ms · ±4px (professional)
    
  
    ทำไม: สีบอกความหมาย แต่สีอย่างเดียวไม่พอสำหรับคนตาบอดสี จึงมี glyph ✕ ใน .riv และการสั่นที่กล่องช่วยดึงสายตา shake ใช้กับ error เท่านั้นเพื่อไม่ให้ความหมายเจือจาง
    

    


    
  
    เคส 5 · วางบนพื้นเข้ม (surface inverse)
    
  
    spinner อยู่ใน banner สีเข้ม · ส่ง surface="inverse"
    
  
    compcml.comp.spinner.rive.color→sys · surface inversecml.sys.color.inverse-primary→refcml.ref.palette.cobalt.80→value#9DAAF3
    
  
    ทำไม: สี primary ปกติมี contrast ต่ำบนพื้นเข้ม inverse เป็นเรื่องของสี ไม่ใช่ motion ไฟล์ .riv จึงไม่ต้องมี animation ชุดใหม่ แค่ bind สีจาก property
    

    


    
  
    เคส 6 · คนเรียกใช้ส่งค่าเอง (escape hatch)
    
  
    ทีม campaign ส่ง props.color="#FF6A00" แทนชื่อ token
    
  
    compcml.comp.spinner.rive.color→ข้าม sys และ refค่าดิบจากคนเรียกใช้→value#FF6A00
    
  
    ทำไม: ใช้ได้แต่จะไม่เปลี่ยนตาม surface หรือ theme อีก Wrapper ควรแสดง warning ใน dev mode และ document ต้องระบุว่า prop ไหนยอมให้ส่งค่าดิบ (สีได้, motion ไม่ได้)
    

    

    


    

    04Motion scheme ควรเป็น mode ไม่ใช่ส่วนหนึ่งของชื่อ
    

    ชื่อแบบ motion.professional.transition.easein รวมสามเรื่อง: ธีม, หมวด และรูปทรง curve ทำให้ token คูณกันเป็น 3 ชุดทุกครั้งที่เพิ่ม role และ component ต้องรู้ชื่อธีมตอน build
    

    
  
    ก่อนmotion.professional.transition.easein
    motion.natural.transition.easein
    motion.playful.transition.easein
    
  
    หลังcml.sys.motion.transition.enter.scale

    05Naming convention
    

    cml.{tier}.{domain}.{category}.{role}.{variant}

// tier     ref | sys | comp
// domain   motion | color | size | border-width | opacity
// category duration | easing | spring | transition | scale | offset | rotate | delay | playback
// role     enter | exit | change | emphasis | loop | spatial | effects
// variant  fade | scale | slide-up | pop | shake | default | fast ...

    • ref ตั้งชื่อตามค่า, sys ตั้งชื่อตามบทบาท

    09State, status, surface
    

    เดิมเรียกรวมว่า feedback & emphasis ตอนนี้แยกเป็นแกนตามความหมาย แต่ละแกนเป็น property ของตัวเองใน View model
    

    

    แกนค่าใครเป็นคนตั้งใน .riv ต้องมี
    


    stateidle · hover · focused · pressed · disabledDev คำนวณจาก eventanimation ทุกค่า
    

    statusnone · success · error · warning · infoคนเรียกใช้ส่ง propanimation + glyph ทุกค่า
    

    surfacedefault · inverseคนเรียกใช้ส่ง propแค่ binding สี
    

    schemeprofessional · natural · playful · reducedcontext หรือ proplayer ต่อ scheme
    

    

    ลำดับความสำคัญ: disabled > status > pressed > hover / focused > idle
    

    


    

    10Contract ของไฟล์ Rive
    

    // spinner.riv · contract v1
Artboard        "Spinner"
State machine   "SM_Main"
View model      "VM_Spinner"

state    : Enum     idle | hover | focused | pressed | disabled
status   : Enum     none | success | error | warning | info
surface  : Enum     default | inverse
scheme   : Enum     professional | natural | playful | reduced
color    : Color    // ← cml.sys.color.primary
size     : Number   // ← cml.sys.size.icon.md
stroke   : Number   // ← cml.sys.border-width.regular
speed    : Number   // ← cml.sys.motion.rive.playback.speed
exit     : Trigger  // code → Rive: เริ่มเล่น animation ออก
exitDone : Trigger  // Rive → code: state machine ยิงเมื่อเล่นออกจบ
    

    ใช้ Trigger property แทน Rive EventRuntime ของ Rive deprecate การฟัง Rive Event และ state change แล้ว แนะนำให้ส่งสัญญาณกลับผ่าน data binding แทน: designer ตั้งให้ state machine ยิง exitDone ตอนเล่นจบ และ dev ฟังด้วย vm.trigger("exitDone").on(...)
    

      
  
    • เงื่อนไข transition ใน SM_Main อ่านจาก property เหล่านี้
      • 
  
    • ใช้ enum แทน boolean หลายตัว เพื่อไม่ให้เกิด state ที่เป็นไปไม่ได้ และเพิ่ม state ได้โดยเพิ่มค่าใน enum
      • 
  
    • ค่าที่ไฟล์ไม่รู้จักให้แสดงเป็น idle ไฟล์เก่าจะไม่พังเมื่อ contract มีค่าใหม่
      •

    12รูปแบบไฟล์ token
    

    แนะนำรูปแบบ W3C Design Tokens (DTCG) ซึ่งมี type transition แบบ composite อยู่แล้ว Spring ยังไม่อยู่ในมาตรฐาน จึงเก็บใน $extensions และเก็บที่มาไว้ที่เดียวกัน
    

    {
  "cml.sys.motion.transition.enter.scale": {
    "$type": "transition",
    "$description": "ของที่ปรากฏขึ้นใหม่ในพื้นที่เดิม ขยายจากเล็กเล็กน้อย",
    "$value": {
      "duration": "{cml.ref.motion.duration.250}",
      "delay": "{cml.ref.motion.delay.0}",
      "timingFunction": "{cml.ref.motion.easing.standard-decelerate}"
    },
    "$extensions": { "cml": {
      "modes": {
        "natural": { "duration": "{…duration.400}", "timingFunction": "{…easing.emphasized-decelerate}" },
        "playful": { "spring": "{cml.ref.motion.spring.expressive-spatial-fast}" },
        "reduced": { "duration": "{…duration.150}", "from": { "scale": 1 } }
      },
      "from": { "opacity": 0, "scale": "{cml.sys.motion.scale.enter.from}" },
      "use": "toast, menu, spinner ที่โผล่ในที่เดิม",
      "avoid": "การเปลี่ยนหน้าทั้งหน้า (ใช้ change.shared-axis)",
      "source": "https://m3.material.io/styles/motion/easing-and-duration",
      "since": "1.2.0"
    }}
  }
}
    

    


    

    13Reduced motion และ accessibility
    

      
  
    • Mode reduced: transition เหลือ fade, offset / scale / rotate = 0, spring ใช้ ζ 1 ไม่มี overshoot ลองได้ที่ปุ่ม Reduced ในแท็บ Mock และ Transitions
      • 
  
    • ใน .riv ให้ designer ทำ layer reduced ที่ loop ช้าลงแต่ยังสื่อว่ากำลังโหลด
      • 
  
    • Spinner ต้องมี role="status" และข้อความ “กำลังโหลด” เมื่อ status เปลี่ยนให้ประกาศผ่าน live region
      • 
  
    • Status มีทั้งสีและ glyph (✓ ✕ ! i) เสมอ
