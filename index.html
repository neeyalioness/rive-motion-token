01แยกสองชั้น: Inner กับ Outer


เคส spinner มีการเคลื่อนไหวสองแบบที่เจ้าของต่างกัน ถ้าไม่แยกตั้งแต่แรก token จะปนกันและทีมจะไม่รู้ว่าแก้ค่าที่ไหน



  
Inner · Rive-ownedสิ่งที่อยู่ในไฟล์ .riv: หมุน, morph วงกลม→หัวใจ→ดาว, สี, ขนาด, ขอบ นักออกแบบ motion ทำใน Rive Editor ฝั่ง code ควบคุมผ่าน state machine inputs และ view model properties เท่านั้น

  
Outer · Host-ownedการเคลื่อนไหวของกล่องที่ห่อ Rive ทั้งก้อน: enter, exit, เลื่อนตำแหน่ง, scale, fade ทำด้วย CSS / Compose / SwiftUI ใช้ duration, easing, spring จาก token ตรง ๆ




กฎข้อเดียวที่ต้องจำคนเรียกใช้ส่ง motionScheme ครั้งเดียว แล้วทั้ง inner และ outer อ่านค่าตาม scheme นั้น Outer อ่านค่า token ตรง ๆ ส่วน inner แปลงเป็น input ของ state machine (เช่น scheme = 2)

ref · primitiveค่าดิบ ไม่มีความหมายเชิงการใช้งาน ตั้งชื่อตามค่า

sys · semanticบอกบทบาท ไม่บอกค่า และเปลี่ยนค่าตาม scheme

cml.sys.motion.spring.spatial.default

  
comp · componentผูกกับชิ้นส่วนของ component ชี้ไปที่ sys เสมอ
cml.comp.spinner.container.enter.duration
cml.comp.spinner.morph.spring




ตัวอย่างการ resolve (scheme = playful):


cml.comp.spinner.container.enter.easing
  → cml.sys.motion.transition.enter.easing
  → cml.ref.motion.spring.expressive-spatial-fast
  → { stiffness: 800, dampingRatio: 0.6 }


Component token ไม่ควรชี้ไป ref ตรง ๆ ถ้าทำแบบนั้นการสลับ scheme จะไม่มีผล







03Motion scheme ควรเป็น mode ไม่ใช่ส่วนหนึ่งของชื่อ


ชื่อแบบ motion.professional.transition.easein รวมสามเรื่องไว้ในชื่อเดียว: ธีม (professional), หมวด (transition) และรูปทรง curve (ease-in) ผลคือ token จะคูณกันเป็น 3 ชุดทุกครั้งที่เพิ่ม role และ component ต้องรู้ชื่อธีมตอน build


M3 แก้ปัญหานี้ด้วย MotionScheme (standard / expressive) ที่ทำงานแบบเดียวกับ light/dark ของสี: ชื่อ token คงเดิม ค่าเปลี่ยนตาม scheme ที่ครอบอยู่ แนะนำให้ CML ทำแบบเดียวกัน



  
ก่อนmotion.professional.transition.easein
motion.natural.transition.easein
motion.playful.transition.easein

  
หลังcml.sys.motion.transition.enter.easing
Figma: Variable collection Motion มี 3 modes = professional / natural / playful
Code: <MotionScheme value="playful">




ยังส่งชื่อเต็มได้ถ้าต้องการ overrideถ้าหน้าหนึ่งเป็น professional แต่อยากให้ spinner ตัวเดียวเด้งแบบ playful ให้ส่ง motionScheme="playful" ที่ตัว component แทนการส่งชื่อ token เต็ม prop นี้ override scheme ที่ครอบอยู่เฉพาะ subtree นั้น


ใน semantic layer ให้ตั้งชื่อตาม บทบาท (enter, exit, persistent, emphasis) ไม่ตามรูป curve (ease-in, ease-out) เพราะ playful อาจใช้ spring แทน curve สำหรับ enter ชื่อ “easein” จะผิดทันที ชื่อ curve เก็บไว้ที่ ref layer







04Naming convention


// โครงสร้าง
cml.{tier}.{domain}.{category}.{role}.{property}

// tier     ref | sys | comp
// domain   motion | color | size | border | opacity | rive
// category duration | easing | spring | transition | scale | fade | offset | rotate | delay | playback
// role     enter | exit | persistent | emphasis | short | medium | spatial | effects ...
// property duration | easing | from | to | stiffness | damping

cml.ref.motion.easing.emphasized-decelerate
cml.ref.motion.spring.expressive-spatial-fast

08States


แบ่งเป็น 4 แกนที่ทำงานพร้อมกันได้ แต่ละแกนเป็น input แยกกันใน state machine




แกนค่าประเภท inputหมายเหตุ



Interaction (ตาม M3 states)enabled · hover · focused · pressed · dragged · disabledboolean: isHover, isFocused, isPressed, isDisabledfocused ใช้ visual เดียวกับ hover ได้ แต่ต้องมีเพื่อคีย์บอร์ด


Feedbacknone · success · error · warning · infonumber: feedback 0–4 (หรือ trigger ถ้าเป็น one-shot)spinner ที่โหลดเสร็จ → success แล้ว exit คือ flow ที่พบบ่อยที่สุด


Emphasisdefault · inverseboolean: isInverseinverse ไม่ใช่ state ของ motion แต่เป็นการสลับชุดสีบนพื้นเข้ม ควรส่งผ่าน color token มากกว่าเป็นคนละ animation


Lifecycleenter · loop · exitouter ควบคุม; inner รับ trigger onExit ถ้าต้องเล่นจบก่อนหายเชื่อม outer กับ inner: outer exit ควรรอให้ inner เล่น success จบ


Schemeprofessional · natural · playfulnumber: scheme 0–2มาจาก prop motionScheme




ลำดับความสำคัญเมื่อชนกัน: disabled > feedback > pressed > hover/focused > idle เช่น ถ้า feedback = error อยู่ แล้วผู้ใช้ hover ให้แสดง error ต่อ (Mock ทำตามลำดับนี้)







09สัญญาระหว่าง design system กับไฟล์ Rive


ทุกไฟล์ .riv ใน asset library ควรมีโครงสร้างเหมือนกัน เพื่อให้ wrapper component ตัวเดียวควบคุมได้ทุกไฟล์


// spinner.riv
Artboard        "Spinner"
State machine   "SM_Main"          // ชื่อเดียวกันทุกไฟล์

// Inputs (state)
isHover     : Boolean
isPressed   : Boolean
isFocused   : Boolean
isDisabled  : Boolean
isInverse   : Boolean
feedback    : Number   // 0 none · 1 success · 2 error · 3 warning · 4 info
scheme      : Number   // 0 professional · 1 natural · 2 playful
onExit      : Trigger

// View model "VM_Spinner" (data binding · props ที่ custom ได้)
color        : Color   // ← cml.sys.color.primary
colorHover   : Color   // ← cml.sys.color.accent.pink
colorPressed : Color   // ← cml.sys.color.accent.yellow
size         : Number  // ← cml.sys.size.icon.md (px)
strokeWidth  : Number  // ← cml.sys.border-width.regular
speed        : Number  // ← cml.sys.motion.rive.playback.speed (1 = ปกติ)


สาม scheme ใส่ในไฟล์อย่างไร



  
A · input scheme ตัวเดียว (แนะนำเป็นค่าเริ่มต้น)หนึ่ง state machine มี layer แยกตาม scheme หรือใช้ blend state ใช้เมื่อ shape เหมือนกันและต่างแค่จังหวะ ไฟล์เดียวดูแลง่าย

  
B · state machine แยกต่อ schemeSM_Professional, SM_Natural, SM_Playful ใช้เมื่อ choreography ต่างกันมาก เช่น playful มีลูกเล่นเพิ่ม wrapper เลือก state machine ตาม prop




ข้อจำกัดที่ต้องตกลงกับทีม motioneasing ใน timeline ของ Rive ถูกกำหนดในไฟล์ ฝั่ง code ส่ง cubic-bezier เข้าไปแทนไม่ได้ ดังนั้น token ของ inner คือ spec สำหรับนักออกแบบ ที่ต้องใช้ค่าเดียวกันตอนทำ timeline (ใส่ไว้ใน handoff) และส่วนที่ปรับจากภายนอกได้คือ input, view model และ playback speed เท่านั้น

  src="spinner.riv"

  }}

Wrapper ทำอะไรบ้าง


    
  
  1. อ่าน motionScheme (จาก prop หรือ context) แล้ว set input scheme
    2. 
  
  2. resolve token ใน props เป็นค่าจริง แล้วเขียนลง view model
    3. 
  
  3. ฟัง pointer / focus / keyboard แล้ว set isHover, isPressed, isFocused เอง คนเรียกใช้ไม่ต้องจัดการ
    4. 
  
  4. resolve transition ตาม scheme เป็น CSS (cubic-bezier หรือ spring ที่แปลงเป็น linear()) แล้ว animate กล่องที่ห่อ
    5. 
  
  5. ตอน unmount: ยิง onExit → รอ inner จบ → เล่น outer exit → ถอด DOM
    6. 








11Reduced motion และ accessibility


    
  
  • เพิ่ม mode ที่ 4 ใน collection Motion: reduced ใช้เมื่อ OS ตั้ง prefers-reduced-motion ทุก transition เหลือแค่ fade, offset / scale / rotate = 0, spring = effects แบบ ζ 1.0
    • 
  
  • Rive: set speed ต่ำลงหรือหยุด loop ตกแต่ง แต่ต้องยังสื่อว่ากำลังโหลด
    • 
  
  • Spinner ต้องมี role="status" และข้อความเช่น “กำลังโหลด” ให้ screen reader เมื่อ feedback เปลี่ยนเป็น success / error ให้ประกาศผ่าน live region ด้วย
    • 
  
  • สีของ feedback ไม่ควรเป็นสัญญาณเดียว ใส่ glyph (✓ ✕ ! i) ด้วยตามที่ Mock ทำ
    •
